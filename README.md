# 利用Cloudflare R2 + Workers搭建在线网盘


[汉化修改自/longern/FlareDrive](https://github.com/longern/FlareDrive)

增加了权限系统，支持多管理员，分别授权目录

cloudflare R2是一个文件储存系统，配合Cloudflare Workers可以实现这样一个网盘系统

### 搭建教程


1. fork该仓库
2. 前往 Cloudflare R2 新建一个私有存储桶，不要开启公开访问
3. 前往Cloudflare Pages新建一个站点，选择连接到Git

4.选择刚刚fork的仓库，点击开始设置
5.项目名称可以修改，其他项目保持默认不动

6.展开环境变量，添加

| 变量名称 | 类型 | 值 |
| --- | --- | --- |
| SESSION_SECRET | 密钥 | 随机生成的至少 32 字符的字符串，不要使用登录密码 |
| AUTH_USERS | 密钥 | `{"admin:替换为管理员密码":"*","user1:替换为用户密码":"user1/,userPublic/"}` |

`AUTH_USERS` 的值是一个 JSON 对象：键为 `账号:密码`，值为允许访问的目录前缀，用英文逗号分隔；`*` 代表所有目录。目录建议以 `/` 结尾，不要添加空目录项。不要把整段 JSON 再包一层引号。

部署后会提供一个访客公共区：访客无需登录即可浏览、预览和下载 `public/` 内文件。上传、覆盖、复制、移动及删除始终需要管理员会话；`GUEST` 不再开放匿名写入权限。其他目录、桶根目录、R2 S3 接口和内部缩略图仍受登录权限保护。

请先以管理员身份在网盘中创建 `public/` 文件夹，再向其中上传要公开分享的文件。请勿将私密文件放入该目录。存储桶保持私有，访客读请求由 Pages Function 通过绑定的 `BUCKET` 从 R2 读取，不需要 `PUBURL`、R2 公共域名或公开访问设置。

**Cloudflare 提示变量名“无效”时：** 不要再创建 `账号:密码` 形式的变量名，冒号会被控制台拒绝。删除表单中无效的那一行，新增名为 `AUTH_USERS` 的密钥，把账号、密码和权限放进上述 JSON 值中。例如单管理员配置为 `{"odell:替换为新密码":"*"}`，登录时用户名填 `odell`，密码填你实际设置的新密码。

旧的账号变量仍兼容，但只在未配置 `AUTH_USERS` 时使用。设置 `AUTH_USERS` 后，以其中的账号列表为准；无效 JSON 会拒绝账号登录，不会退回旧配置。修改密码时替换 JSON 中的旧账号密码键，不要保留旧密码条目。

更新代码、变量或密钥后，需要重新部署对应的生产或预览环境才会生效。旧版本代码不识别 `AUTH_USERS`，请先确保部署使用本版本。`SESSION_SECRET` 用于签名登录会话，更换它会使现有登录失效；如果密码或此密钥曾出现在公开截图中，请更换并使用“密钥”类型保存。

设置好后点击**开始部署**

7.前往 Pages -> 项目 -> 设置 -> Functions -> R2 存储桶绑定，将私有 R2 存储桶绑定到变量名 `BUCKET`

8.在部署页面重新部署即可

### 会话升级说明

v2 会话使用签名令牌，Cookie 只包含基于 `SESSION_SECRET` 和账号配置生成的 HMAC 不透明标识、签发时间、过期时间及随机值，不包含密码、可逆编码的账号密码或普通密码哈希。`AUTH_USERS` 格式无需修改；升级部署后旧版 Cookie 一律拒绝，用户需要重新登录，公共区访问不受影响。会话有效期仍为 7 天，保留 `HttpOnly`、`Secure`、`SameSite=Lax`。

每次鉴权都会按当前已部署的账号配置检查身份与目录权限：替换密码、删除账号或更换 `SESSION_SECRET` 会使原令牌失效，目录权限变更也会应用到后续请求。若恢复完全相同的旧账号密码或旧签名密钥，满足当前配置且尚未过期的旧 v2 令牌可能重新有效。

这仍是无状态令牌，不是服务端存储的会话 ID：退出只清除当前浏览器 Cookie，无法单独撤销已被复制的令牌；副本在过期或相关配置变更前仍可使用。令牌仍须作为凭证保护。若旧 Cookie 或密码曾泄露，必须更换受影响的密码，仅升级格式或轮换签名密钥不能消除已泄露的密码。

### 验证

使用 Node.js 22.6 或更高版本，先运行 `npm ci`，再运行 `npm test`，验证账号配置、密码变更、公共区只读边界、目录权限以及前端登录和导航状态。测试不需要连接 Cloudflare。

在 PowerShell 中运行 `npx wrangler pages functions build functions --outfile "$env:TEMP/r2-functions-check.js"` 可检查 Functions 打包。本项目尚未配置独立的 lint 和 TypeScript 类型检查命令。
